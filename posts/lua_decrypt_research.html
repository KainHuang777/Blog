二、資產封裝結構分析

2.1 Unity AssetBundle 封裝層

遊戲 Lua 資產以 Unity AssetBundle (格式：UnityFS v8, Unity 2022.3.x) 封裝分發。自 V3.89.0 起，資產由單一封裝檔拆分為多個業務模組 bundle：

Bundle 名稱用途體積（約）

每個 bundle 內含一個 TextAsset 類型物件（m_Name = "Lua"），其 m_Script 欄位儲存了已加密的原始位元組資料。

三、XOR 加密原理與逆向方法

3.1 XOR 加密數學原理

XOR（互斥或）是一種對稱性串流加密方法，其核心特性：加密與解密使用完全相同的運算。

加密：ciphertext[i] = plaintext[i]  XOR  key[i % key_length]
解密：plaintext[i]  = ciphertext[i] XOR  key[i % key_length]

數學依據：A XOR B XOR B = A（自反性）

3.2 金鑰發現過程

發現方法：透過對 APK 進行靜態反編譯（jadx / apktool + IL2CPP 分析），在 Native 層符號或 C# 反編譯產物中搜尋硬編碼字串常量。金鑰為明文存於可執行檔中，屬於混淆而非真正加密。

目標應用程式的 XOR 金鑰為一段固定的 65 字元長字串：

*(Vd7@4&(*)VK~5hjLH-+~N7J!83jkl)*6(&#65gdsw43t515fg(*^)#kJLHG

3.3 Python 核心解密實作

def xor_decrypt(data: bytes, key: str) -> bytearray:
    key_bytes = key.encode('utf-8')
    key_len = len(key_bytes)
    result = bytearray(len(data))
    for i in range(len(data)):
        result[i] = data[i] ^ key_bytes[i % key_len]  # 循環金鑰 XOR
    return result

3.4 Archive 拆包結構（C# BinaryReader 移植）

XOR 解密後，得到的明文資料遵循以下自訂打包格式（Little-Endian）：

[4 bytes] int32  → Lua 模組總數 N
重複 N 次：
  [2 bytes] int16  → 檔名長度
  [L bytes] string → 模組路徑（UTF-8，含"/"路徑分隔符）
  [4 bytes] int32  → 字節碼長度 M
  [M bytes] bytes  → xLua 5.3 字節碼資料

此格式直接對應遊戲客戶端的 C# BinaryReader 讀取邏輯，每個模組完整路徑（如 Model/Network/BI/BIManager）被還原為資料夾層級，便於閱讀導航。

四、xLua 字節碼標頭逆向

4.1 標準 Lua 5.3 vs xLua 差異對照

位置（Offset）欄位名稱標準 Lua 5.3xLua 遊戲版本
Byte 0–3Magic Number\x1bLua\x1bLua（相同）
Byte 4Version0x530x53（相同）
Byte 5Format0x000x01 ← 需修正
Byte 6–11LUAC_TAIL固定 6 bytes相同
Byte 14Instruction Size0x040x08 ← 需修正

4.2 標頭修正實作

def patch_lua_header(data: bytearray) -> bool:
    # 驗證是否為 Lua 5.3 字節碼
    if data[0:4] == b'\x1bLua' and data[4] == 0x53:
        data[5]  = 0x00  # Format:           0x01 → 0x00
        data[14] = 0x04  # Instruction Size: 0x08 → 0x04
        return True
    return False  # 非 Lua 字節碼，跳過

4.3 假邊界問題：研究歷程關鍵突破（V10）

問題根源：早期版本（V1–V9）透過掃描 Lua 魔術數字（\x1bLua）定位各個 chunk 邊界，但 Lua 字節碼內部的字串常數也可能含有相同的位元組序列（如 AdvertisementWindow.lua 內嵌了另一段序列化 Lua 閉包），導致約 3,400 個假 chunk 與多個檔案被截斷損壞。
V10 突破：完全捨棄邊界掃描法，改為直接依據 Archive 打包結構中的長度欄位精確讀取每個 chunk。此方法完全免疫假邊界干擾，實現 100% 提取成功率，且速度大幅提升。
